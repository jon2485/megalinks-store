# Mega Links v172 — הרחבת העיצוב לכל סביבת המנהל

המשתמש אישר ב־18.10.2026 את הרחבת העיצוב לכל הצד הניהולי, בענף `design/admin-tabler-v172` וב־Railway Staging בלבד. נקודת הבסיס היא `b3e62a8473a2f808144a802bafb0fadb622db8cc`. נקודת שחזור זו נשמרה ב־GitHub בשם `restore/admin-ui-before-full-20261018`. גרסת Staging הקודמת לשחזור היא Deployment `c514597a-277c-461a-9d12-826c2f725d31`, commit `37204b0c81ab35f8b42d1e2989b674fcfad88ef1`. שחזור הוא של קוד/פריסה בלבד, ללא איפוס `/data`.

## השינוי

- **מרכז הבקרה:** תשעת תורי העבודה המקוריים לצד חלון הטיפול האמיתי במסך רחב; במסך צר הם מסתדרים מעליו. חיפוש, רענון, כל הלשוניות, כניסה לפרטים, חזרה לרשימה, ספירות, טיפול בתשלומים, אישורים ו־dirty guard נשמרו. בוטלה מגבלת הגובה הפנימית של חלון הטיפול כדי שטופס ארוך ימשיך בגלילת המסמך.
- **ניווט:** תשעה תחומים ו־21 קישורים מקוריים; ארבע קבוצות מתקפלות באמצעות details/summary טבעיים. הקבוצה הפעילה נפתחת כברירת מחדל. חיפוש עם ניקוי נגיש והחזרת focus לשדה. כל ניווט רגיל עובר דרך ctx.go המקורי; קיצורי פתיחת לשונית חדשה נשמרו ותיקון NEW-01 נשאר בתוקף.
- **מסכים פנימיים:** כותרות, טבלאות, כרטיסי נתונים, סרגלי פעולות, מסננים, שדות וכפתורים מקבלים שפה אחידה בכל מסכי הניהול: הזמנות, דיווחי תשלום, חשבוניות, הטענות, חשבונות חודשיים, לקוחות והרשאות, תיק לקוח, אתרים/רמות/מחירונים, Sheets, ספקים והתחשבנות, כתבות/אישורים/פרסום, מבצעים וחבילות, שירות, הנחיות, חיבורים, דוחות ויומנים.
- **חלונות פנימיים:** עיצוב ניהולי ל־Radix Dialog/AlertDialog/Select/Popover, גבולות גובה לפי viewport, שדות 16px בטלפון ו־focus ברור. תכולת הטפסים, פעולות אישור/ביטול, נעילות busy וכל שמירה מקוריות. ה־CSS של portals מותנה ב־`body:has(.admin-design-v172)`; מחוץ למסך מנהל מאומת אין התאמה לסלקטורים האלה.
- **מותג ונגישות:** Heebo/Arial הקיימים, כחול כהה וטורקיז של Mega Links, משטחים לבנים, ריווח אחיד, פינות מתונות, סכומים tabular, hover/focus/disabled, reduced motion ו־forced colors. אין נתוני דוגמה, פעילות מומצאת או תלות חדשה.

לא אוחדו רכיבים עסקיים ולא הועברו פעולות למימוש אחר. תצוגת המנהל כולה מקבלת את שכבת העיצוב; כל רכיב React עסקי ממשיך לבצע את הפעולות שלו. [מפת הכיסוי לכל המסכים והנתיבים](./full-screen-coverage.csv) כוללת גם aliases ונתיבי פרטים. מפת 1,002 הפקדים ו־93 קבוצות הפעולות המקוריות נשארת בתוקף; התוספת מתארת את העיצוב של אותם מיקומים.

## שימור פעולות ובידוד

רק שלושה קובצי מוצר השתנו מול נקודת השחזור החדשה: `app/admin-shell.tsx`, `app/admin-lobby.tsx`, `app/admin-design-v172.css`. `workspace.tsx` לא השתנה בהרחבה הזו; שלוש תוספות התצוגה המאומתות מהשלב הקודם נשארו. אין שינוי בשרת, API, Database, Auth, מחיר, payload, version, הרשאה, handler שמירה, רכיב משותף או ממשק לקוח/ספק.

בדיקת AST חדשה משווה במדויק את כל קריאות הפונקציה בדשבורד ואת כל מאפייני האירועים, הערכים, הזמינות, ה־refs והבחירה שלו למקור. בדיקת בידוד משווה את יתר המקור ל־Git blobs המקוריים ומאשרת שכל סלקטור CSS דורש את מחלקת המנהל או את guard ה־portal החי. אין flag קבוע על body, איפוס נתונים או הפעלת קוד רדום.

B1–B8 נשארו לפי ההכרעה הקיימת: לא הופעלו לשוניות legacy שמנורמלות להזמנות, helpers רדומים או CatalogGrid הישן; היקפי lobby/מסך מלא נשארו; עלויות ספק נשארות בהרשאת מנהל; אין פעילות אחרונה מומצאת. פערי popstate/dirty המקוריים לא תוקנו במסגרת עיצוב. הם אינם מוצגים כיכולות חדשות או כבדיקות שעברו.

## בדיקות שהורצו

**48 סקריפטי בדיקה עברו:** 41 בדיקות ממשק/handlers/חוזים/מחירים/ניווט ועוד 7 חבילות על הגרסה הבנויה בסביבה מבודדת. בניית Vinext הסופית, TypeScript ולינט שני קובצי ה־React ששונו עברו. ראיות מפורטות: [full-verification.json](./full-verification.json).

בבדיקות השרת המקומיות: פרטיות ספקים **999 בדיקות**, אינטגרציית תמחור **149**, תיק לקוח וחשבונות חודשיים **250**, ביקורת תשלומים **120**, חיבור Sheets מדומה עם הרשאות/conflict/stale, שער התחברות **37**, ותשעה נכסי JS/CSS אמיתיים. אלה בדיקות fixtures ומסד D1/R2 מקומי זמני, ללא גישה לנתונים חיים וללא משלוח תשלומים/דואר/Sheets אמיתיים.

שתי בדיקות ישנות (`customer-articles-ui`, `users-payment-ui`) נכשלו על ציפיות טקסט שכבר אינן תואמות לגרסת המקור. אותו כשל שוחזר במקור השמור לפני השינויים. עודכנו רק assertions כדי לבדוק את ה־aliases המקוריים ואת מסך ההזמנות הפעיל; ה־helpers נבדקים בנפרד ולא הופעלו. בנוסף הותאמו בדיקות מעטפת לכותרת החדשה ול־details, בלי להחליש את בדיקות 21 הנתיבים או שמירת הפעולות.

הביקורת הסטטית המחמירה של Frontend Design Premium אינה נקייה: אותם **71 ממצאים קיימים** (23 ownership ו־48 violations), **אפס ממצאים חדשים** בהשוואה לדוח המקורי. אין טענה לעמידה מלאה ב־WCAG או ב־Premium. לא הורחב ההיקף לתיקון מנגנונים עסקיים או shared UI כדי לשנות ממצא היסטורי.

## מגבלות אימות

אין כלי control-browser זמין בסביבה זו. הוראות Sites קובעות: “If control-browser is unavailable, skip browser QA”. לא הותקן דפדפן ולא הופעל מסלול עוקף. לא בוצעו בדיקות רינדור/הידרציה/הקלקה אמיתית/מקלדת או תמונות השוואה ב־375/768/1440px. בדיקות React fixtures ו־CSS אינן תחליף להן. העיצוב לכל המסכים מיושם, אך גימור חזותי ופונקציונליות בדפדפן דורשים בדיקת קבלה במחשב ובמובייל ב־Staging.

אין אימות חי מקצה לקצה של שמירת מחירים/לקוחות, חיובים, זיכויים, PDF, התחשבנות או Sheets לאחר שינוי התצוגה. לא נבצע פעולות כאלה על נתונים קיימים כדי לטעון שהכול נבדק. המקור והחוזים שלהן נשמרו והבדיקות המבודדות עברו.
