# פריסת מנהל v172 ל־Railway Staging — NEW-01

18.10.2026. המשתמש אישר במפורש תיקון NEW-01 ופריסה מבוקרת ל־Staging בלבד לאחר מעבר כל הבדיקות הזמינות, ללא אישור נוסף. אישור זה אינו אישור Production ואינו מציג בדיקות דפדפן כעוברות.

## התיקון

`app/admin-shell.tsx`: בחירת יעד רגילה סוגרת את תפריט הניהול המתקפל, מאפסת חיפוש כפי שהיה קודם, ומחזירה פוקוס לכפתור הפתיחה אם הוא גלוי. קישור עם Ctrl/Cmd/Shift/Alt או לחצן אמצעי שומר את ההתנהגות הטבעית שלו ואת העורך הנוכחי. הקריאה ל־`ctx.go(page)` נשארת כפי שהייתה; לא הוחלף dirty guard ולא נוספה פעולת שמירה.

התנהגות NEW-01 מכוסה ב־`tests/admin-design-navigation.mjs`, כולל פוקוס לכפתור גלוי, סגירה בבחירה ושימור הקריאה ל־guard. קובצי תמחור/הזמנות/אתרים/הרשאות/מסד ו־API לא שונו. DESIGN.md עודכן לתאר את התנהגות הניווט.

## בדיקות לאחר התיקון

- 22 קובצי בדיקות עברו: 19 קובצי הרגרסיה, פרטיות ספקים (911 בדיקות מבודדות), שער Staging (37 בדיקות), ו־9 קובצי JS/CSS שאליהם מפנה SSR.
- בדיקות החוזים הפעילו את כל 27 שדות האתר, רמות, שיוך, מחירים אישיים, ייבוא, שמירה/שגיאה, ניווט והזמנות מול fixtures בלבד. לא בוצעו פעולות עסקיות חיות.
- TypeScript, לינט ניווט ובניית Vinext עברו. בדיקת הבידוד אישרה 371 קבצים מקוריים זהים וכל CSS חדש תחום למנהל. אין שינוי ב־API, Auth, Database, לוגיקה עסקית או רכיבי לקוח/ספק משותפים.
- לפני הפריסה נבדקה כניסה בחשבון מנהל Staging הקיים, בלי לפרסם credentials. 7 נתיבי מנהל החזירו HTML עם 200, 4 נתיבי נתונים החזירו JSON עם 200, ו־9 קובצי CSS/JS החזירו קוד אמיתי עם 200. ללא התחברות המסכים/קובץ שנבדק הוסטו לכניסה ונתיבי API החזירו 401. `/healthz` החזיר 200. לא נשמרו HTML, נתוני לקוחות או cookies בדוח.
- בדיקות דפדפן, רינדור מחשב/מובייל, הקלקות DOM והידרציה אינן זמינות בסביבה הנוכחית. בדיקות ה־HTTP וה־React אינן מחליפות אותן. המשתמש יבדוק את התצוגה ב־Staging המוגנת לאחר הפריסה שאושרה.

הראיות המדויקות נמצאות ב־[staging-predeploy-checks.json](./staging-predeploy-checks.json). 71 ממצאי האיכות הסטטיים שהיו קיימים קודם אינם תקלות חדשות מהתיקון; פערי dirty/popstate ושאר בדיקות הקבלה החיות נשארים מתועדים בדוח הקבלה.
